# AGENTS.md

## Назначение рабочей папки

Это рабочее пространство (не код-репозиторий) пилотного проекта «каскадная система на основе LLM для автоматизированной экспресс-оценки стартапов по экспертным критериям». Полное описание — в `Паспорт пилота.md` (цель, гипотеза, шкала, архитектура, риски, критерии успеха). Читайте его перед любыми изменениями методологии.

## Состав файлов

- `Паспорт пилота.md` — мастер-документ пилота: шкала, правила, каскадная архитектура (4 шага), формат JSON-результата, план работ.
- `Приложение №2 - Пример разметки.md` — эталонный пример того, как эксперт применяет рубрику к тексту проекта (структура разметки: балл, критерии со статусами, подтверждающие фрагменты, антипризнаки, недостающие данные, обоснование).
- `Рубрики. N. <название>.md` — 9 рубрик параметров оценки (полное заключение). Единая структура: назначение → правило применения (4 критерия) → «Разграничение с другими рубриками» → критерии с индикаторами, антипризнаками и порогом подтверждения. Пилот на рубриках 1–3 подтвердил применимость подхода; корпус 9 рубрик не «заморожен» и дорабатывается целиком при устранении дублей.

## Доменные правила, которые нельзя нарушать

- Оценка строится каскадом: **извлечение оснований (без балла) → выставление балла по рубрике → проверка согласованности**. Не смешивать факты и интерпретацию.
- Каждый вывод опирается на конкретный фрагмент текста проекта либо явно фиксируется «подтверждение не найдено».
- Шкалы: критерий 0–2 (0 — отсутствует, 1 — формально есть, 2 — убедительно), параметр 0–5 по числу подтверждённых критериев из 4 (см. «Паспорт пилота», раздел «Шкала оценки»).
- Слабое/частичное упоминание индикатора не подтверждает критерий; выраженные антипризнаки отменяют критерий даже при формальных упоминаниях. Критерий подтверждается, только если найденные фрагменты закрывают «Порог подтверждения», зафиксированный для него в рубрике.
- Результат оценки — структурированный JSON с полями: `parameter_name`, `score`, `evidence_spans`, `observed_signs`, `anti_signs`, `missing_data`, `why_not_lower` (опц.), `confidence`.
- Параметр «влияние на технологический суверенитет» — вне границ пилота: рубрика 9 строит индикаторы только по внутренним следам текста, вывод о суверенитете не делается (нужна внешняя рамка сопоставления).
- Разграничение рубрик: один фрагмент может подтверждать критерии разных рубрик, но у каждой рубрики свой уникальный вопрос — раздел «Разграничение с другими рубриками» в каждом файле обязателен. Ключевые границы: рынок (масштаб потребности) ≠ путь к применению (рубрики 2 vs 7); задел (что сделано) ≠ путь вперед (3 vs 7); решение в целом ≠ собственная разработка (4 vs 5).

## Конвенции документов

- Все документы на русском языке. Новые документы и правки — тоже на русском.
- Именование рубрик: `Рубрики. N. <название параметра>.md`.
- Термины фиксировать как в паспорте: «рубрика» = параметр оценки (критерии + признаки/антипризнаки + порог подтверждения + единая шкала), «подтверждающие фрагменты», «антипризнаки», «порог подтверждения», «каскадная схема».
